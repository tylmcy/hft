一、线程模型总览

IO 线程 (Tomcat/WebSocket)

  • • HTTP-IO-Thread: 接收请求，解析参数
  • • WebSocket-IO-Thread: 连接管理，消息推送
  • • 多线程并发，无状态
  • • 不直接访问 Chronicle Map
  • • 请求转发给业务线程处理

订单网关线程 (OrderGateway)

  • • 多线程并发处理订单请求
  • • 风控检查: 读 Chronicle Map
  • • compute 原子冻结资金/持仓
  • • 冻结成功写入 Order Queue
  • • Entry 级别锁，不同账户并发

清算服务线程 (N+2)

  • • TradeReader (1): 读 Trade Queue，分发到内存队列
  • • ClearingWorker (N): N=CPU核心数，compute 原子更新
  • • ORDER_UPDATE: PENDING→NEW (订单入撮合确认)
  • • TRADE: 幂等清算，更新账户/持仓
  • • CancelProcessor (1): 处理撤单解冻
  • • Entry 级别锁，不同账户并发执行
  • • 推送 WebSocket 成交回报
  • • Queue Index 持久化到 progress.dat

Queue Index 持久化

  • • 存储位置: progress.dat (Chronicle Map)
  • • Key: "trade_queue_index"
  • • Value: 已处理的最大 index
  • • 更新时机: 清算成功后
  • • 重启恢复: 从 index+1 开始

幂等设计 (TradeId 去重)

  • • 存储位置: processed_trades.dat
  • • Key: tradeId (Long)
  • • putIfAbsent 原子检查+写入
  • • 防止重复清算
  • • 保证数据一致性

风控服务线程 (RiskControl)

  • • 多线程并发风控检查
  • • 只读取 Chronicle Map
  • • 资金充足性检查 O(1)
  • • 持仓限额检查 O(1)
  • • 不写入，多读取者安全

异步持久化线程

  • • 单线程批量写入 H2
  • • 仅用于历史查询
  • • 不参与主链路
  • • 不访问 Chronicle Map
  • • 不影响交易性能

撮合引擎线程

  • • 单线程处理，无锁设计
  • • 从 Order Queue 读取订单
  • • 价格优先时间优先撮合
  • • 写入 Trade Queue
  • • 不访问 Chronicle Map
