HFT Trading System V12 — Full Trading Pipeline

Order Submission → Risk Control → Matching → Clearing → Settlement → Snapshot → Recovery
⚡
Single-JVM Architecture
All components run in a single JVM process. No distributed coordination overhead. AccountWorker, MatchingEngine, ClearingWorker each run on a dedicated single thread, eliminating lock contention and ensuring serial consistency for state mutations.
🔒
RPO = 0 Guarantee
All state changes are persisted to Chronicle Queue before memory update. Snapshot + incremental replay ensures zero data loss on restart. Atomic file writes (tmp → data → MD5 → rename) prevent snapshot corruption.
🚀
100K TPS Design
Batch processing (50-100 events/batch) amortizes CQ write overhead. In-memory ConcurrentHashMap for hot path. Virtual threads for HTTP with CompletableFuture sync pattern. ZGC eliminates GC pause impact on P99 latency.
🛡
Three-Layer Idempotency
Order layer: Snowflake ID + putIfAbsent() prevents duplicate order creation. Trade layer: tradeId dedup prevents double settlement. Settlement layer: tradeId_orderId composite key ensures exact-once clearing. Critical for CQ replay during recovery.
